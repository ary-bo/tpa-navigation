TPA NAVIGATION — PROJECT CHANGE LOG
===================================
Purpose
-------
This file is the chronological, conversation-independent record of implemented
project changes. Keep it concise enough to transfer into a new conversation,
but detailed enough to identify the exact code, behavior, verification status,
and next steps.

Repository
----------
https://github.com/ary-bo/tpa-navigation
Primary branch: main
Companion technical handover:
docs/TPA_Project_Documentation.md

Operating rules
---------------
1. After every implemented project change, append a dated entry here.
2. Record the user-approved requirement, actual behavior implemented, files,
   branch, commit SHA, backup/rollback reference, and verification status.
3. Clearly distinguish source inspection, automated tests, user/browser
   confirmation, and deployment status. Never claim a test or deployment that
   was not performed.
4. Update docs/TPA_Project_Documentation.md whenever a project phase or feature
   is completed. This change log supplements, and does not replace, that
   technical handover document.
5. At the start of a new conversation, read this file and the technical
   handover document, then inspect current GitHub main before making changes.
6. If a change is made but not committed, record it as pending/uncommitted.
7. Preserve previous entries. Correct mistakes with a dated clarification;
   do not silently erase history.

How to use this file in a new conversation
------------------------------------------
Ask the assistant to read:
- docs/PROJECT_CHANGELOG.txt

Then continue from the latest entry after verifying current repository state.
